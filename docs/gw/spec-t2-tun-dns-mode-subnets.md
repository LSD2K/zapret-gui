# Спека T2: TUN без захвата DNS хоста и подсети в agh_routes

Ветка `debian-gw`. Форк работает движком под панелью gw-panel на роутере gw
(Debian 13, sing-box-extended 1.14.1). Две независимые правки, один коммит на каждую.

## A. `make_tun_inbound`: `dns_mode: disabled`

Проблема (gw, 24.09.2026): sing-box 1.14 при старте TUN на Linux регистрирует в
systemd-resolved на линке `singbox-tun` DNS-сервер `<address+1>` (172.19.0.2), домен
`~.`, `Default Route: yes` (опция TUN `dns_mode`, дефолт `hijack`, с 1.14.0). Всё, что
на хосте резолвит через nss (python, apt, git, certbot), уходит в TUN, получает fakeip
и идёт через прокси. На gw это чинится вручную ключом `"dns_mode": "disabled"` в
`gw.json`; движок при пересборке конфига его потеряет.

Сделать:
- `core/singbox_config.make_tun_inbound(...)`: новый kwarg `dns_mode: str = "disabled"`.
  Если непустой, в inbound кладётся `"dns_mode": dns_mode`. Пустая строка = ключ не
  писать (для sing-box < 1.14, который незнакомые ключи отвергает).
- `set_tun_inbound(...)` принимает и пробрасывает `dns_mode` (тот же дефолт).
- Оба вызова `make_tun_inbound` в `build_fakeip_config` и во втором билдере (около
  строки 1080) оставляют дефолт `disabled`. Никаких настроек в UI не добавлять.
- Докстринг: зачем, с какой версии, ссылка на инцидент (эта спека).
- Тесты: `tests/test_singbox_config.py`, `tests/test_singbox_fakeip.py`: в TUN-inbound
  есть `dns_mode == "disabled"`; с `dns_mode=""` ключа нет; `auto_route`/`stack` как были.

## B. `agh_routes`: поле `subnets` у правила → `ip_cidr` в sing-box

Панель ведёт модель «сервис → способ». Приложения, ходящие по IP без DNS (Telegram на
датацентры), fakeip не ловит. Сейчас на gw руками: маршрут подсетей в TUN (networkd)
плюс правило `{"ip_cidr": [...], "outbound": "Finland"}` в `gw.json`. Маршруты остаются
делом панели (специфика gw), правило sing-box должен писать движок вместе с
`domain_suffix`, чтобы был один путь применения и один рестарт.

Контракт (панель пишет параллельно под него):
- `PUT /api/agh-routes`: у правила новое поле `subnets`: список строк IPv4 CIDR
  (`["149.154.160.0/20", "91.108.4.0/22"]`), либо текст с разделителями как у
  `domains` (`_split_tokens`). Отсутствует = `[]`.
- `GET /api/agh-routes` отдаёт правила с `subnets` (нормализованные).
- `/api/agh-routes/plan` и `apply`: в `rules[]` инфо добавить `subnets: <int>` и
  `subnets_sample: [...]` (до 5).
- В `gw.json` для правила с непустым `subnets` движок кладёт отдельное правило
  `{"ip_cidr": [...], "outbound": tag}` сразу после правила `domain_suffix` того же
  правила (если доменов нет, только `ip_cidr`). Место в `route.rules` то же, что у
  доменных (после `hijack-dns`, до `tun-in`), `merge_singbox_rules` уже это делает.
  Порядок между `domain_suffix` и `ip_cidr` не важен: у fakeip-трафика есть домен, у
  IP-трафика нет.

Сделать в `core/agh_routes.py`:
- `_clean_rules`: `subnets` принимает список или текст, каждый токен через
  `ipaddress.ip_network(tok, strict=False)`; только IPv4 (IPv6 отбросить с
  предупреждением «IPv6 не поддерживается»), мусор отбросить с предупреждением как у
  доменов, адрес без маски = `/32`, хранить `str(net)`, дедуп с сохранением порядка.
- `_rules_part`: правило с `subnets` и `outbound` валидно даже без доменов (не
  «нет доменов, пропущено»). Одинаковая подсеть в двух правилах: первое выигрывает,
  предупреждение как у доменов. Вложенные подсети между правилами: только
  предупреждение. В `desired` после доменного правила добавить `{"ip_cidr": subnets,
  "outbound": tag}`.
- `_applied.singbox.rules` хранит всё, что поставили (включая `ip_cidr`), тогда
  следующее применение снимает старые правила точным совпадением, чужие ручные
  `ip_cidr` в `gw.json` не трогаются (как сейчас).
- Строки AdGuard (`render_agh_lines`) подсетей не касаются.
- Веб-страница движка для agh_routes может `subnets` не показывать, но не должна их
  терять при сохранении (проверить, что фронт шлёт правило целиком или бэкенд
  сохраняет поле, если фронт его не прислал: если фронт пересылает только известные
  поля, добавить `subnets` в пересылку).
- Тесты `tests/test_agh_routes.py`: нормализация (`149.154.167.41` → `/32`,
  `149.154.167.41/20` → `149.154.160.0/20`, IPv6 и мусор отброшены с предупреждением),
  правило только с подсетями, `desired` содержит `ip_cidr` после `domain_suffix`,
  повторное применение снимает старые `ip_cidr`, ручное чужое `ip_cidr` остаётся.
- Документ по API agh_routes в `docs/` (найти существующий, дополнить полем).
