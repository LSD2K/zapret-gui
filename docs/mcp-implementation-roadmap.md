# Порядок реализации MCP-сервера: сессии, бюджет контекста, последовательность

> Спутник [`docs/mcp-server-plan.md`](mcp-server-plan.md). Тот документ отвечает
> на вопрос **что делать**, этот — **как это делить между сессиями ИИ-агента**,
> чтобы качество не падало от переполнения контекста.
>
> Расчёт под Claude Opus 5 в Claude Code с окном 200K токенов. Важно: качество
> проседает **задолго** до лимита — чем больше в контексте «фонового» текста,
> тем хуже модель удерживает инварианты и тем чаще ломает то, что уже работало.
> Поэтому бюджеты ниже консервативные, а не «сколько влезет».

---

## 0. Почему нельзя просто отдать план целиком

Реальные размеры того, что агент захочет прочитать (замерено в репозитории):

| Что | Размер | ≈ токенов |
|---|---|---|
| `docs/mcp-server-plan.md` (сам план) | 104 КБ | **~30K** |
| `.claude/skills/nfqws2-strategies/SKILL.md` | 93 КБ | **~27K** |
| `CoderManual.md` | 52 КБ | ~15K |
| `AGENTS.md` | 20 КБ | ~6K |
| `core/strategy_scanner.py` | 90 КБ | ~26K |
| `core/nfqws_manager.py` | 73 КБ | ~21K |
| `core/firewall.py` | 73 КБ | ~21K |
| `core/blockcheck.py` | 55 КБ | ~16K |
| `web/js/pages/strategies.js` | 137 КБ | ~39K |
| все `api/*.py` | 492 КБ | ~140K |
| все `tests/*.py` (160 файлов) | 1.5 МБ | ~440K |

Наивный старт «прочитай AGENTS + CoderManual + скил + план и начинай» съедает
**~78K токенов до первой строки кода** — почти 40% окна на чтение, ещё до
разведки кода, самих правок, прогонов тестов и их починки. Дальше начинается
авто-компакт, а компакт в середине отладки — это ровно то место, где агент
«забывает» half-done правку и делает вторую половину неправильно.

**Три приёма, которые решают проблему:**

1. **Нарезать план на задания.** Первым делом (сессия S0) разложить
   `mcp-server-plan.md` на `docs/mcp/00-contract.md` (общие правила, ~1.5K
   токенов, читается всегда) и по файлу на сессию `docs/mcp/NN-*.md`
   (2–4K токенов, читается только своей сессией). Сам план остаётся как
   источник, но в работу подаётся нарезка.
   **Сделано:** нарезка лежит в [`docs/mcp/`](mcp/00-contract.md).
2. **Писать скил `mcp` с самого начала, а не в конце.** В плане он стоял в
   последнем PR — это ошибка. `.claude/skills/mcp/SKILL.md` должен появиться
   в первой же сессии и дополняться каждой следующей: он превращается в
   сжатый слепок проекта (300–400 строк, ~4K токенов) и заменяет последующим
   сессиям чтение уже написанного кода.
3. **Эстафета через `docs/mcp/HANDOFF.md`.** Одна страница, которую каждая
   сессия перезаписывает в конце: что готово, какие контракты зафиксированы,
   где следующая сессия должна подключиться, какие грабли найдены. Следующая
   сессия читает её вместо того, чтобы реконструировать состояние по диффам.

## 1. Бюджет одной сессии

| Фаза | Потолок | Что в нём |
|---|---|---|
| Вход (перед первой правкой) | **≤ 35K токенов** | контракт + задание + HANDOFF + скил `mcp` + точечная разведка |
| Рабочий пик | ≤ 120K (60%) | + написанный код, вывод тестов, итерации |
| Порог остановки | **60%** | дописать HANDOFF, закоммитить, закрыть сессию |

Правила, которые держат вход в 35K:

- **Читать целиком** можно файл до ~300 строк. Больше — только `grep -n` по
  конкретным именам и `sed -n 'A,Bp'` по найденным диапазонам.
- **Никогда не открывать целиком:** `strategy_scanner.py`, `firewall.py`,
  `blockcheck.py`, `diagnostics.py`, `web/js/pages/strategies.js`, `app.py`,
  `api/*.py` пачкой, `tests/*` пачкой.
- **Скил nfqws2 читать по разделам.** Он нужен целиком только сессии S11
  (сборка стратегий). Остальным хватает §2 (инварианты), §12 (сборка argv),
  §13 (сканер) — это ~4K токенов вместо 27K.
- **Разведку отдавать субагенту.** «Найди, где регистрируются роуты и как
  устроен ответ ошибки» — задача для `Explore`: он прочитает пол-репозитория,
  а в основной контекст вернётся абзац.
- **Тесты гонять точечно:** `python3 -m pytest tests/test_mcp_*.py -q`, а не
  все 160 файлов. Полный прогон — один раз в конце сессии.

## 2. Карта сессий

Одна сессия = один PR = одна ветка. «Читает» — оценка входа, «пишет» —
порядок величины нового кода вместе с тестами.

## 3. Последовательность

```
S0 ─ S1 ─ S2 ─ S3 ─┬─ S4 ─┬─ S6 ─ S7 ─ S8 ─ S9 ─ S10 ─ S11 ─┬─ S16
                   └─ S5 ─┘                                   │
                                    S12 ─ S13 ─ S14 ─ S15 ────┘
                                    (можно вести параллельно после S2)
```

**Жёсткие зависимости** (нарушать нельзя):
`S1 → S2` (реестр поверх протокола) · `S2 → всё остальное` (шаблон инструмента)
· `S3 → S10/S11` (без справочников эксперименты бессмысленны) · `S7 → S10`
(эксперимент применяет стратегии) · `S8 → S10` (эксперимент меряет пробами)
· `S9 → S10` (общий мьютекс до движка, иначе сканер и эксперимент подерутся).

**Мягкие** (порядок на ваш вкус): S4 и S5 между собой; вся волна E относительно
волн C и D.

### Быстрый маршрут до первой пользы

Если хочется увидеть ценность раньше, чем через шестнадцать сессий:
`S0 → S1 → S2 → S3 → S4 → S7 → S9 → S10`. Восемь сессий — и модель уже
подбирает стратегии с обратной связью. Запись настроек (S6), туннели (S5),
shell (S12) и самоправка (S13) в этот маршрут не входят и делаются потом.

### Порядок по риску

Shell (S12) и самоправка (S13) стоят в конце **намеренно**: это самые опасные
инструменты, и включать их разумно на сервере, который уже проверен в бою.
Технически они независимы и могут быть написаны раньше — но не включены.

## 4. Регламент одной сессии

**Старт (в этом порядке, ничего лишнего):**

1. `docs/mcp/00-contract.md` — общие правила (~1.5K).
2. `docs/mcp/NN-<своё>.md` — задание (~3K).
3. `docs/mcp/HANDOFF.md` — что оставила предыдущая сессия (~1K).
4. `.claude/skills/mcp/SKILL.md` — текущий слепок реализации (~4K).
5. Точечная разведка: `grep -n` по именам из задания; `Explore`-субагент,
   если надо «понять, как тут принято».

**Работа:**

6. Сначала один эталонный кусок целиком (первый инструмент, первый метод) —
   и только потом остальные по его образцу.
7. Тесты пишутся в той же сессии, что и код. Сессия без тестов не закрывается.
8. Прогон: `python3 -m pytest tests/test_mcp_*.py -q` → `make lint`.

**Финиш (обязательный ритуал, без него следующая сессия начнёт с археологии):**

9. Обновить `.claude/skills/mcp/SKILL.md` — новые инструменты, контракты, грабли.
10. Перезаписать `docs/mcp/HANDOFF.md`: сделано / контракты / следующий шаг /
    что оказалось не так, как написано в задании.
11. `CHANGELOG.md`, коммит, PR.

**Когда останавливаться, не доделав:** контекст перевалил за 60%, или начались
авто-компакты, или дифф вырос за ~700 строк. Тогда: дописать HANDOFF, закоммитить
то, что работает и покрыто тестами, остаток переписать в задание следующей
сессии. Половина PR с зелёными тестами лучше, чем целый PR, собранный после
трёх компактов.

## 5. Частые способы всё испортить

| Соблазн | Чем кончится |
|---|---|
| «Прочитаю план целиком, чтобы видеть картину» | 30K токенов фона в каждой сессии, компакт на середине отладки |
| «Сделаю read-only инструменты одной большой сессией» | 20+ инструментов, к концу модель забывает форму первых и пишет их иначе |
| «Заодно поправлю сканер, раз уж открыл» | S9 существует ровно для того, чтобы правка сканера была отдельным, проверяемым PR |
| «Скил напишу в конце, когда всё устаканится» | каждая сессия реконструирует состояние по коду вместо 4K токенов выжимки |
| «Сессия длинная, но я же слежу» | после второго компакта модель уверенно дописывает то, чего уже нет в контексте |
| «Объединю S10 и S11 — они про одно» | вместе они требуют ~60K только справочников; именно здесь цена ошибки выше всего |

## 6. Про модель

Всё, что связано со стратегиями nfqws2 (S9–S11), с shell и самоправкой
(S12–S13) и с фундаментом (S1–S3), стоит делать Opus 5: там цена ошибки —
неработающий обход или недоступный роутер. Однотипные обёртки над готовыми
менеджерами (S4, S5, частично S14) — это копирование эталона из S2, их можно
отдать младшей модели, если важна экономия; качество там держится тестами и
шаблоном, а не рассуждением.

Не полагайтесь на расширенное окно как на замену дисциплине: 1M контекста не
делает 300K осмысленного текста удержанным — он делает его дорогим.
