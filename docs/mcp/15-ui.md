## Блоки страницы

1. **Включение и статус.** Переключатель «Включить MCP-сервер»; адрес точки
   доступа и **сколько инструментов публикуется прямо сейчас** — число
   меняется при переключении разрешений, это самая наглядная обратная связь
   во всём интерфейсе. Если GUI слушает `127.0.0.1` — подпись, что MCP
   доступен только с роутера. Если работает по обычному HTTP —
   предупреждение, что **токен виден в каждом запросе**, и ссылка на
   включение HTTPS.
2. **Токен.** «Сгенерировать», «Показать», «Скопировать», «Ротировать» +
   предупреждение, что токен даёт доступ к роутеру.
3. **Разрешения.** Чекбоксы с человеческим описанием риска; эффект
   мгновенный (`tools/list_changed`), без перезапуска GUI. `experiments`
   без `control`+`probes` — визуально заблокирован с пояснением.
4. **Сниппеты подключения** (кнопка «копировать»):
   - Claude Code:
     `claude mcp add --transport http zapret-gui http://<ip>:8080/api/mcp --header "Authorization: Bearer <token>"`
   - Claude Desktop / LM Studio (`mcpServers`, **без поля `type`**):
     `{"mcpServers": {"zapret-gui": {"url": "…/api/mcp", "headers": {"Authorization": "Bearer <token>"}}}}`
   - VS Code (`.vscode/mcp.json`) — **с `inputs`**, чтобы редактор *спрашивал*
     токен, а не хранил его в файле (такой файл не коммитят).
   - stdio: `zapret-gui mcp --stdio`
5. **Журнал вызовов** (последние 50) + кнопка «Отменить последнее изменение»
   (`mcp_undo_last`).
6. **Активный эксперимент** (S10): вариант, прогресс, **сколько осталось до
   авто-отката**, кнопки «Закоммитить» / «Откатить сейчас».
7. **Правка кода (self-edit)** (S13): переключатели `self_edit` /
   `self_edit_core` с предупреждением («модель сможет переписать сам GUI;
   при неудачном рестарте изменения откатятся автоматически»), список
   снимков с «Показать diff» / «Откатить», индикатор «применена правка,
   ждёт подтверждения: осталось N с», кнопка «Выгрузить патч».
8. **Shell-доступ** (S12): два переключателя с явным предупреждением
   («полный доступ к роутеру от имени root»), список последних команд с
   кодом возврата, **кнопка «Запретить shell немедленно»** (гасит оба
   переключателя и убивает активные async-задачи) и список ожидающих
   подтверждения команд с «Подтвердить» / «Отклонить» — чтобы человек мог
   подтвердить опасное из GUI, а не только токеном из модели.

Блоки 6–8 показываются только если соответствующая сессия сделана; иначе —
скрыты, а не «в разработке».

## Правила

1. Стиль страницы — как у остальных: vanilla-JS, IIFE, `API.*`, i18n, без
   новых зависимостей и без сборки.
2. **Токен не логировать и не класть в URL.** Показ — по явному клику.
3. Все тексты предупреждений — по-русски, в i18n-словаре, а не в разметке.
4. Опрос статуса — щадящий (эксперимент и shell-задачи меняются секундами,
   но роутер слабый): один интервал на страницу, остановка в `destroy`.

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_mcp_ui_api.py` | роуты, которые дёргает страница, отвечают в нужной форме; «запретить shell немедленно» действительно гасит оба разрешения и снимает активные задачи |
| `node --test tests/*.js` | если в проекте есть JS-тесты для страниц — добавить по образцу; иначе минимум: файл страницы парсится и экспортирует `render`/`destroy` |

## Приёмка

- Включение, выдача токена и раздача разрешений — целиком из GUI, **без
  перезапуска**.
- Число инструментов на странице меняется синхронно с чекбоксами.
- Кнопка «Запретить shell немедленно» работает при активной async-команде.
- Страница остаётся отзывчивой во время идущего эксперимента.

## Грабли

- **Не собирай статус из нескольких вызовов в JS.** Один роут — один ответ;
  иначе страница будет мигать на слабом роутере.
- **`self_edit` и рестарт GUI.** После `code_apply` страница потеряет связь —
  показать это как ожидаемое состояние («GUI перезапускается, ждём…»), а не
  как ошибку сети.
- **Предупреждения должны быть страшными ровно настолько, насколько
  обосновано.** `shell_full` — это root; текст не должен это смягчать.
