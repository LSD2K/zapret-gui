## Что написать

```

```

Линтер — в `core/`, а не внутри MCP: он пригодится UI (страница стратегий) и
покрывается обычными юнит-тестами без поднятия сервера.

### `strategy_compose` (`strategies_write`)

**Декларативно собрать стратегию.** Вход — профили:

```json
{"profiles": [{"filter": {"proto": "tcp", "ports": "443", "l7": "tls",
                           "hostlist": "youtube"},
                "desync": [{"fn": "fake", "params": {"blob": "tls_clienthello_www_google_com"}}],
                "blobs": ["tls_clienthello_www_google_com"]}]}
```

Выход: готовый argv + preview-команда + **предупреждения линтера**.
Использует `strategy_builder.autowrap_bare_trick` и карту lua-функций —
не переписывает их.

### Линтер (`core/strategy_lint.py`)

Минимальный набор правил (расширяется по скилу §5/§6/§15):

| Правило | Почему |
|---|---|
| голый приём без фильтра | попадёт на весь трафик, а не на цель — классический «тихий 0%» |
| неизвестная lua-функция | в Lua неизвестное имя не ошибка загрузки, а тихо неработающая стратегия |
| отсутствующий blob | движок стартует, десинк не применяется |
| нарушенный порядок `--lua-init` | функции не зарегистрированы к моменту вызова |
| фильтр без портов при `l7` | зависит от версии zapret2 — предупреждение, не ошибка |

Каждое предупреждение: `code` (стабильный символ), `message` (по-русски),
`section` (ссылка на раздел скила). Различать **error** (собранный argv
заведомо не сработает) и **warning** (подозрительно, но бывает осознанно).

### `strategy_validate` (`strategies_write`)

`nfqws_manager.dry_run()` через `--intercept=0`: парсинг опций + наличие
файлов + **исполнение lua-init**. Возвращает `returncode`, вывод, и — если
вывод узнаваем — те же `hints`, что и в S10.

Это единственная проверка, которая ловит ошибку **внутри lua**, а не только
в командной строке. Именно поэтому она должна быть отдельным инструментом, а
не «частью сохранения»: модель обязана иметь возможность проверить, ничего
не сохраняя.

## Приёмка

- Модель собирает стратегию из описания («TLS на 443 для списка youtube,
  fake с готовым blob»), получает валидный argv и проходит `strategy_validate`
  без ручных подсказок.
- Стратегия с несуществующей lua-функцией **не доходит** до эксперимента:
  линтер или `dry_run` её отбивают с понятным текстом.
- Сборка через `strategy_compose` и сборка через UI дают **одинаковый argv**
  для одного и того же набора профилей (тест).

## Грабли

- **Не изобретай синтаксис.** Любой флаг, которого нет в скиле и в выводе
  `zapret://nfqws2/cli`, — это выдумка. Если сомневаешься — проверь `dry_run`
  на устройстве, а не «по памяти».
- **`autowrap_bare_trick` уже решает часть задачи** — не пиши второй
  автообёртыватель рядом.
- **Ложное предупреждение дороже пропущенного.** Модель верит линтеру
  буквально: получив warning, она начнёт переписывать работающую стратегию.
  Сомневаешься в правиле — не добавляй его.
- **Порядок аргументов nfqws2 значим** (профили разделяются, `--lua-init`
  идёт раньше использования). Проверяй сборку сравнением с эталоном
  `strategy_builder`, а не глазами.
