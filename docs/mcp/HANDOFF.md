### Зафиксированные контракты

**Четыре текста, четыре работы.** README — «зачем, как включить, чем
рискую» (и называет каждый инструмент, сгруппированные **по
разрешению**); скил — сигнатуры и грабли для правящего код;
`CoderManual.md` §5.8/§6/§13 — куда класть новый инструмент;
`docs/mcp/*` — архив. Дублировать между ними нельзя: разойдутся.

**Новый инструмент = четыре правки.** `core/mcp/tools/<домен>.py` +
строка в таблице скила + имя в README + число в
`tests/test_mcp_tool_counts.py`. Первые три стережёт
`tests/test_mcp_tools_docs.py`.

**Формат строки таблицы скила** (его разбирает сторож регэкспом):

```
| `имя` | scope | да/нет | `tools/файл.py` | сигнатура | описание |
```

`scope` — дословно из объявления (`read` для read-only), `mutating` —
`нет` либо `**да**`, файл — `tools/<модуль>.py`.

### Что оказалось не так, как написано в задании

1. **«Скил 300–400 строк» — оценка из S0, когда скила не было.** К S16
   он вырос до 2000 строк накопленного знания пятнадцати сессий.
   Сжимать его до 400 значило бы выбросить ровно то, ради чего он
   писался. Сделана **ревизия**, а не переписывание: снят устаревший
   заголовок, добавлены сигнатуры и разделение с README.
2. **Запись `mcp-spec` в `docs/upstream.json` уже существовала** (её
   завёл S14). S16 дополнил её тем, чего не хватало: `content_checks` и
   README в `mentions`.
3. **Приёмка на железе (§17 плана) в этой сессии невозможна** — нет
   роутера. Восемь пунктов переехали чек-листом в `TODO.md`; три из них
   (не рвёт управление, переживает перезагрузку, влезает в 128 МБ) в CI
   не воспроизводятся в принципе, и это сказано прямо.
4. **README называет все 93 инструмента.** Выглядит избыточно для
   пользовательского текста, но группировка идёт **по разрешению**: он
   решает, какой переключатель включить, и должен видеть, что именно
   тот открывает. Это же требование стережёт тест.

### Грабли

- **Регэксп строки таблицы и `[^|]*` через перевод строки.** Скрипт,
  добавлявший колонку сигнатур, склеил две соседние строки ДРУГОЙ
  таблицы (строка с двумя ячейками и следующая за ней):
  `[^|]` спокойно матчит перевод строки. Правка таблиц регэкспом
  обязана либо запрещать перевод строки в классе, либо идти построчно.
- **`make upstream-offline` падает от добавления файла в `mentions`.**
  `mentions` — не «где упоминается», а «где ОБЯЗАНА стоять
  pinned-версия дословно». Добавив README, надо было написать в нём
  `2025-06-18` — что и сделано (заодно это полезно читателю: клиент
  подключается по ревизии).
- **`content_checks` проверяются только с сетью.** Offline-режим их не
  трогает, поэтому регэксп легко написать неверным и узнать об этом
  через неделю от CI. Проверено вручную вызовом
  `check_upstream.check_branch_paths()` на живом апстриме.
