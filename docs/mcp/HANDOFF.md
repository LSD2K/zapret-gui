# MCP: эстафета между сессиями

> Одна страница, которую **каждая сессия перезаписывает в конце**. Следующая
> сессия читает её вместо того, чтобы реконструировать состояние по диффам.
> Держать в пределах ~120 строк: это не журнал, а снимок «где мы сейчас».
>
> Шаблон записи — в конце файла.

### Зафиксированные контракты

**`GET /api/mcp/ui/state`** — единственный источник данных страницы:
`{ok, info, access, audit, experiment, code, shell}`. `info` — дословно
тело `/api/mcp/info` (общая `api.mcp.info_payload()`). Блоки
`experiment`/`code`/`shell` всегда несут `available`; при `false`
страница скрывает карточку целиком. Токена в ответе нет никогда.

**Каждый мутирующий роут панели возвращает свежий `info`** — счётчик
инструментов меняется в тот же запрос, без второго похода на сервер.

**`/api/mcp/ui/` — не MCP.** Bearer-токен туда не пускает (`app.py`),
только авторизация GUI. Ослабить это нельзя: панель раздаёт
разрешения.

**Токен:** `POST /api/mcp/ui/token {action: "rotate"}` отдаёт значение
один раз; `GET /api/mcp/ui/token` — по явному клику и пишет в журнал
факт показа. `GET /api/config` отдаёт `mcp.token` как `***`.

**Тексты предупреждений** — `web/js/i18n/{ru,en}.js`, ключи
`mcp.warn.token|http|loopback|rotate|restart|shell|self_edit|panic` и
`mcp.risk.<разрешение>` (11 штук). **S16 берёт их в README дословно.**

### Что оказалось не так, как написано в задании

1. **Роуты живут в `api/mcp_ui.py`, а не в `api/mcp.py`.** Задание
   говорит «дополнить `api/mcp.py`», но панель — это не протокол: она
   решает, что модели МОЖНО, и её нельзя пускать по Bearer-токену.
   Отдельный файл делает эту границу видимой, а `api/mcp.py`
   оставляет транспортом.
2. **Страница не ходит в `/api/mcp/info`.** Тот роут loopback-only
   (S1), а GUI открывают из браузера на LAN-адресе — страница была бы
   пустой у всех, кто админит роутер обычным способом. Тело вынесено в
   `info_payload()` и отдаётся обоими роутами.
3. **«Ссылки на включение HTTPS» нет, потому что включать нечего.**
   Своего TLS у GUI не существует (в `DEFAULT_CONFIG.gui` нет ни
   `ssl`, ни сертификатов). Предупреждение называет настоящие пути:
   `bind = local` + ssh-туннель, stdio-мост, обратный прокси.
4. **`mcp.transports.http` переключателем не показан** — он ни на что
   не влияет (долг S14), и кнопка «отрезать себе доступ» пользователю
   не нужна. `sse` — настоящий флаг и переключается.
5. **Тексты в i18n, остальная разметка — по-прежнему русским текстом
   в коде страницы.** Так сделаны все страницы проекта (`i18n/*.js` —
   два десятка общих ключей). В словарь уехало то, что требует
   задание и что переиспользует README: предупреждения и риски
   разрешений.
6. **Попутно закрыта утечка:** `GET /api/config` отдавал `mcp.token`
   открытым текстом любому, кто открыл GUI. Делать страницу, которая
   прячет токен, поверх роута, который его отдаёт, бессмысленно.

### Грабли

- **`/api/config` маскирует, но PUT возвращает маску обратно.**
  Записанная дословно `***` — это лок-аут по паролю GUI и мёртвый
  токен. Теперь тело PUT проходит `ConfigManager.strip_masked()` (тот
  же приём, что у импорта конфига).
- **Полная перерисовка снимает галочку под рукой.** Ответ опроса
  приходит через секунду после клика и возвращает прежнее состояние
  чекбокса. Отсюда флаг `_busy` на время действия и перерисовка блока
  только при смене его подписи (`_section(id, html, [signature])`).
- **`const` в `node:vm` не попадает в `globalThis`.** Страница —
  `const McpPage = (…)()`; после `runInContext` её нет среди свойств
  контекста. Достаётся явным `globalThis.__page = McpPage`.
- **Тест «отменить последнее изменение» нельзя звать по-настоящему.**
  В общем прогоне рядом живут снимки других тестов, и `undo_last()`
  откатил бы чужой firewall (поймано на прогоне). Проверяется
  проводка на подменённой `audit.undo_last`.
- **`stop_all_jobs()` обязан идти вместе со снятием разрешений.**
  Кнопка, которая гасит только флаги, оставляет живой `sleep 30` от
  root и обещает больше, чем делает.
- **Из S14 остаётся в силе:** `from core import X` не ловит отсутствие
  модуля (в `api/mcp_ui.py` — `importlib.import_module`); рассылка
  `tools/list_changed` идёт опросом на круге keep-alive, поэтому
  запись разрешений из панели её не требует.
- **Из S13/S12:** `ConfigManager.set()` не пишет на диск — без
  `save()` разрешения вернутся при перезапуске GUI; имя снимка
  переиспользуется; дедмен в памяти не откатывает ничего.
