# MCP: эстафета между сессиями

> Одна страница, которую **каждая сессия перезаписывает в конце**. Следующая
> сессия читает её вместо того, чтобы реконструировать состояние по диффам.
> Держать в пределах ~120 строк: это не журнал, а снимок «где мы сейчас».
>
> Шаблон записи — в конце файла.

### Зафиксированные контракты

**Staging:** `code_patch`/`code_write` НЕ пишут на диск проекта. Ответ
несёт `staged: true`, `applied: false`, `diff`, `staging: {count,
files, bytes}`. Выкинуть накопленное — `code_patch(drop=true[, path])`.

**Снимок:** `<config_dir>/code-snapshots/<snap-YYYYmmdd-HHMMSS>/` =
`manifest.json` + `files/<rel>`. Состояния `pending` → `applied` →
`committed` | `reverted`. Манифест пишется ДО правки файлов; сортировка
снимков — **по `created_ts`, а не по имени** (имя переиспользуется
после ротации); незакрытый снимок ротация не трогает.

**Сторож:** `python3 -B -m core.code_guard --snapshot <id> --timeout N
--commit-ttl N --config-dir DIR [--no-restart-wait]`, запускается
`start_new_session=True` ДО просьбы о перезапуске. Манифест правят
двое, поэтому сторож дописывает только свои поля в свежую копию
(`_patch`).

**Текст про разрыв соединения** — один и тот же в описании
`code_apply`, в `hint` ответа и в `server._instructions`.

### Что оказалось не так, как написано в задании

1. **`code_check` без слепка дерева проверял бы не то.** Задание
   говорит «`python3 -c "import core.foo"` с `cwd` проекта», но правка
   лежит в staging, и импортировался бы файл С ДИСКА — то есть
   проверка доказывала бы исправность старой версии. Появился
   `build_shadow()`: симлинки на всё дерево + правленые файлы
   настоящими. Слепок собирается по ВСЕМ накопленным правкам, даже
   если проверить просят одну.
2. **Health-check может быть недостоверен сам по себе.** Закрытый
   порт, включённая Basic-авторизация, другой bind — и сторож откатил
   бы исправный GUI. Поэтому он сначала проверяет, отвечает ли GUI
   ПРЯМО СЕЙЧАС (его запустил живой GUI); не отвечает — работает
   только по дедмену подтверждения.
3. **«GUI не ушёл на перезапуск» — не провал.** Если команды
   перезапуска нет или она не сработала, код лежит на диске
   незагруженным. Откатывать за это нельзя (правка могла быть в `.js`),
   решает дедмен подтверждения; в манифесте остаётся
   `restart_observed: false`.
4. **`redact_text` к коду не применяется** (в отличие от `file_read` в
   S12). Маска сломала бы точное совпадение в `code_patch`: строка
   `token = cfg.get(…)` уехала бы как `token = ***`. Секретов в
   исходниках GUI нет — они в `settings.json`, а он вне корня и
   запрещён.
5. **Четырнадцатого инструмента «выкинуть staging» не появилось** —
   задание фиксирует тринадцать. Это `code_patch(drop=true)`.
6. **`self_edit.protected` из настроек оказался недостаточен.**
   Список, лежащий в правимом файле, — это не защита: `CORE_PROTECTED`
   в коде добавляет к нему сам `code_editor.py` и `mcp/registry.py`
   (в нём проверяется scope).
7. **Дрейф файла** в задании не назван, но без него первое же
   обновление GUI посреди сессии заканчивалось бы тихим затиранием
   чужой правки: `apply_staged` сверяет sha256 исходника.

### Грабли

- **Имя снимка переиспользуется.** `snap-<время>` уникально в пределах
  секунды, а после ротации освободившееся имя берётся снова —
  сортировка по строке объявляла самый новый снимок самым старым.
  Сортировать только по `created_ts` из манифеста.
- **`__pycache__` и `-B`.** Без `-B` слепок писал бы байт-код по
  симлинку в настоящее дерево; без исключения `__pycache__` из слепка
  проверка «проходила» бы на старом байт-коде.
- **`ConfigManager.set()` не пишет на диск.** Сторож читает ФАЙЛ, и
  тест, который не позвал `cfg.save()`, проверяет дефолты, а не то,
  что поставил.
- **Полная перезапись манифеста теряет чужое поле.** Пишут двое (GUI и
  сторож) — только merge на свежую копию.
- **Из S12 осталось в силе:** атомарная запись создаёт НОВЫЙ файл (без
  `chmod` теряется `+x`); дедмен в памяти не откатывает ничего;
  `from core import X` берёт атрибут пакета, а не `sys.modules` —
  подменять надо функции модуля.
- **Из S9/S10/S11:** CLI поднимает движок мимо `nfqws_control`;
  `restore()` не сверяет argv; синглтон движка экспериментов общий на
  процесс; линтовать надо СОБРАННЫЙ argv.
