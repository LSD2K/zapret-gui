## Что написать

### 1. `README.md` — раздел «Управление через ИИ (MCP)»

Пользовательский, не инженерный: зачем это нужно, как включить, как
подключить Claude Desktop / Claude Code / LM Studio, что модель может и чего
не может, **честный абзац про риски** (токен = доступ к роутеру; модель
видит домены и логи).

Отдельные подразделы:

- **Shell.** Чем `shell_readonly` отличается от `shell_full`; почему полный
  доступ стоит включать только для локальной модели (LM Studio на своей
  машине); что прочитанный лог или конфиг может содержать чужой текст,
  который модель примет за инструкцию.
- **Самоправка.** Что модель может переписывать сам GUI; как работает
  авто-откат; почему после `code_apply` рвётся соединение; что локальные
  правки надо выгружать патчем, иначе их затрёт обновление.

## Приёмка фичи целиком (§17 плана) — на реальном роутере

Не «прогнать тесты», а проверить руками, с секундомером:

1. **Не подвисает.** Во время скана, эксперимента и `shell_exec_async`
   веб-интерфейс остаётся отзывчивым.
2. **Не рвёт управление.** После намеренно вредной последовательности
   (гасим интерфейс, флашим firewall, ломаем модуль) GUI и SSH остаются
   доступны **сами**, без вмешательства человека. Это главный приёмочный тест.
3. **Переживает перезапуск.** Токен, разрешения, журнал, снимки кода и
   незакоммиченные правки читаются после `reboot`; незавершённый эксперимент
   не оставляет применённой временную стратегию.
4. **Честная обратная связь.** Коды из фиксированных словарей, одинаковые
   поля при успехе и неуспехе, «не знаю» вместо выдумки; получив отказ,
   модель понимает, что включить.
5. **Не течёт.** Секреты не появляются ни в одном ответе; лог не забивается
   при переборе токена; буферы ограничены; временные файлы чистятся.
6. **Влезает в роутер.** 128 МБ RAM: ответы ≤ лимита, одновременных тяжёлых
   операций не больше одной, память MCP-слоя не растёт от числа вызовов
   (проверить сутки под периодическим опросом).
7. **Работает у живых клиентов.** Claude Code, Claude Desktop, LM Studio и
   хотя бы один OpenAI-совместимый мост: список инструментов виден, вызовы
   проходят, длинные операции не отваливаются по таймауту клиента.
8. **Сценарии Приложения D проходят целиком** — без ручных подсказок между
   шагами (`grep -n "Приложение D" -A 20 docs/mcp-server-plan.md`):
   «почему не открывается rutracker», «подбери стратегию для YouTube»,
   «сколько свободно места», «поставь htop», «перезапусти dnsmasq»,
   «покажи системный лог», «перезагрузи роутер», «что ты вообще можешь».

## Грабли

- **README пишется для человека, который боится это включать.** Если после
  раздела непонятно, чем рискуешь, — раздел не готов.
- **Скил не должен быть копией README.** README — «зачем и как включить»,
  скил — «точные сигнатуры и грабли для того, кто правит код».
- **Приёмка на железе не заменяется тестами.** Пункты 2, 3 и 6 в CI не
  воспроизводятся в принципе.
