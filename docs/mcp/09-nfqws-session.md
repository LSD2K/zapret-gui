# S9 — `core/nfqws_session.py`: общий мьютекс и снимок состояния

> Вход: [`00-contract.md`](00-contract.md) + этот файл + `HANDOFF.md` + скил `mcp`.
> **Сессия-рефакторинг без новой функциональности.** Единственная её цель —
> чтобы сканер и будущий движок экспериментов не подрались за nfqws2.
> Существует отдельно именно для того, чтобы правка сканера была отдельным,
> проверяемым PR, а не «заодно» внутри S10.

## Почему это нельзя сделать внутри S10

Сканер уже умеет сохранять и восстанавливать состояние (`_save_current_state`
/ `_restore_previous_state`). Движку экспериментов нужно ровно то же самое.
Если написать второй такой механизм рядом — два процесса будут независимо
«восстанавливать как было», и победит тот, кто закончит вторым: роутер
останется с чужой стратегией. Поэтому сначала общий примитив, потом движок.

## Что прочитать (≈25K)

- `core/strategy_scanner.py` — **только четыре метода через `grep -n`**:
  `_save_current_state`, `_restore_previous_state`, `_probe_one_strategy`,
  `_run_baseline_test` (+ `_wrap_trick_args`, `_deep_probe`, если они
  задевают состояние). Прочитать их диапазоны через `sed -n 'A,Bp'`.
  **Файл целиком не открывать — 90 КБ, ~26K токенов.**
- `core/nfqws_manager.py` — `grep -n "def start\|def stop\|def restart\|def get_status\|def compose_command"`.
- `core/firewall.py` — `grep -n "def apply\|def remove\|def get_status"`.
- `core/strategy_state.py` — целиком (небольшой), если сканер его трогает.
- Место, откуда S7 берёт защиту от конкуренции («идёт скан») — его надо
  заменить на настоящий мьютекс.

## Что написать

```
core/nfqws_session.py   — общий контекст «временно применить argv и
                          гарантированно вернуть как было» + глобальный
                          мьютекс nfqws2/firewall
```

Изменить: `core/strategy_scanner.py` — перевести сохранение/восстановление
состояния на общий модуль, **без изменения поведения сканера**.

### Контракт модуля

Примерная форма (уточнить по тому, что реально делает сканер):

```python
from core.nfqws_session import get_nfqws_session

session = get_nfqws_session()          # синглтон, как остальные менеджеры

with session.acquire(owner="experiment", timeout=0) as lock:
    # занято → исключение/None с указанием текущего владельца и времени захвата
    snapshot = session.snapshot()      # стратегия, запущен ли nfqws2, firewall
    try:
        session.apply_temporary(argv)  # применить firewall + запустить движок
        ...
    finally:
        session.restore(snapshot)      # гарантированно вернуть как было
```

Требования:

1. **Владелец виден.** Занятый мьютекс должен уметь сказать *кто* его держит
   (`scan` / `experiment` / `ui`) и *с какого времени* — из этого строятся
   человеческие тексты отказов в S7 и S10.
2. **Мьютекс переживает исключения** и не залипает: захват с таймаутом,
   освобождение в `finally`, защита от повторного освобождения.
3. **Снимок полный**: активная стратегия, запущен ли nfqws2 и с какими argv,
   применён ли firewall и какой. Восстановление идемпотентно — повторный
   `restore` ничего не ломает.
4. **Процессный, а не потоковый.** GUI — один процесс, но сканер может жить
   в воркере: смотри, как это устроено сейчас (`CoderManual` §8), и сделай
   так, чтобы блокировка работала в реальной схеме, а не только в тестах.
   Если нужен файловый lock — класть его рядом с `settings.json`, не в
   `/tmp`.

## Правило сессии: поведение сканера не меняется

Это главный критерий. Не «улучшать по дороге», не переименовывать поля, не
трогать логику проб и baseline. Только вынести общий механизм и позвать его
из сканера. Если по пути нашёлся баг в сканере — **записать в HANDOFF, а не
чинить здесь**: иначе в PR будет не видно, что сломало поведение.

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_nfqws_session.py` | захват/освобождение; второй захват при занятом → отказ с именем владельца; освобождение при исключении; `restore` идемпотентен; снимок содержит стратегию, состояние движка и firewall |
| существующие `tests/test_strategy_scanner*.py` | **прогнать без изменений** — они и есть сторож «поведение не изменилось». Пришлось править тест → значит, поведение изменилось; остановись и разберись |

## Приёмка

- Все существующие тесты сканера зелёные **без правок**.
- Сканер и `strategy_apply` не могут работать одновременно, и отказ
  объясняет, кто держит блокировку.
- Дифф в `strategy_scanner.py` состоит из замены вызовов, а не из новой
  логики.

## Грабли

- **Сканер уже содержит `finally`-восстановление.** Не оставляй два уровня
  восстановления, которые борются друг с другом: либо сканер делегирует
  целиком, либо его `finally` становится вызовом `session.restore`.
- **Мьютекс не должен блокировать чтение.** `nfqws_status`, `strategy_list`
  и прочее read-only берут блокировку **только** если им действительно нужен
  консистентный снимок; иначе GUI встанет во время скана.
- **Таймаут захвата 0 — это не «ждать вечно».** Ноль означает «не ждать,
  сразу сказать занято»: модель должна получить ответ, а не висеть.

## Оставить следующим

`HANDOFF.md` + скил: точная сигнатура `acquire/snapshot/apply_temporary/
restore`, где лежит lock, кто уже его берёт, что именно попало в снимок.
S10 строится на этом модуле целиком.
