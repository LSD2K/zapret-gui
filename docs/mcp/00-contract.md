## 1. Что строим

MCP-сервер внутри `zapret-gui`: внешняя модель (Claude Desktop/Code, LM Studio,
Cline) через `POST /api/mcp` управляет всем функционалом GUI и — главное —
**подбирает и отлаживает стратегии nfqws2, видя результат каждого своего
изменения** (применил → измерил → откатил). Сверх этого: shell ко всему
роутеру и самоправка модулей GUI на устройстве с авто-откатом.

Референс идей — MCP в [b4](https://docs.b4core.app/ru/docs/settings/mcp/).
**Копировать b4 не нужно**: где наш путь надёжнее — идём своим (§16 плана).

## 2. Жёсткие ограничения (нарушение = переделка PR)

- **Только stdlib.** Код едет на роутер с `python3-light`. Никаких `mcp`,
  `fastmcp`, `pydantic`, `jsonschema`, `httpx`, `requests`. JSON Schema
  генерируем и валидируем сами (мини-валидатор ~150 строк: типы, `required`,
  `enum`, диапазоны, `minItems/maxItems`).
- **Русский язык** в комментариях, docstring'ах, логах, UI, коммитах и
  документации. Поле `description` инструмента — **английский + русский одной
  строкой** (его читает модель), ≤ 300 символов.
- **Ничего не ломать.** Существующие REST-роуты, формат ответов
  (`{ok: bool, …}`), поведение сканера и firewall остаются как есть.
- **Никаких `shell=True`** и никакой конкатенации в команды: только
  `argv`-списки. Единственная точка исполнения произвольной строки —
  `core/shell_exec.py` через `["sh", "-c", command]`, и она закрыта
  разрешением `shell_full`.
- **`core/mcp/tools/*` — тонкие обёртки.** Вся логика живёт в существующих
  менеджерах (`get_*_manager()`). Не хватает функции — она добавляется в
  соответствующий `core/*.py` (и становится доступна UI/CLI), а не пишется
  внутри MCP.
- **Ответы компактные.** Их читает модель с ограниченным контекстом:
  пагинация, лимиты, `truncated: true`, обрезка по `mcp.limits.response_kb`.

## 3. Форма инструмента (эталон, задаётся в S2)

```python
@tool(
    name="strategy_experiment_start",   # <домен>_<действие>, snake_case
    scope="experiments",                # одно из значений §4
    mutating=True,
    title="Run A/B strategy experiment",
    description=("Apply nfqws2 strategy variants, probe targets and return "
                 "per-target metrics, engine log tail and hints. Auto-reverts "
                 "after ttl_sec unless committed. / Прогнать варианты стратегии "
                 "с измерением результата и авто-откатом."),
    schema={"type": "object", "properties": {...}, "required": ["variants"]},
)
def strategy_experiment_start(args: dict) -> dict:
    """Запустить эксперимент (обёртка над core/strategy_experiment)."""
```

Результат `tools/call`:

```json
{"content": [{"type": "text", "text": "<тот же JSON строкой>"}],
 "structuredContent": {"...": "машинно-читаемый dict"},
 "isError": false}
```

- **Ошибка исполнения инструмента — не JSON-RPC ошибка**, а нормальный
  результат с `isError: true` и человекочитаемым текстом: модель должна
  уметь её прочитать и исправиться.
- JSON-RPC ошибки (`-32700/-32600/-32601/-32602/-32603`) — только про сам
  протокол.
- Одинаковые поля при успехе и неуспехе; коды — из фиксированных словарей
  (`core/testers/probe.py:PROBE_CODES` и т.п.), никаких свободных строк.
- «Не знаю» вместо выдумки: если описания/данных нет — так и отвечаем и
  показываем, что есть рядом.

## 4. Модель разрешений (`settings.json → mcp.permissions`)

Все по умолчанию `false`, кроме чтения. Инструмент объявляет `scope` и
`mutating`; `tools/list` отдаёт **только разрешённые**; вызов неразрешённого —
`isError` с текстом «включите разрешение X в настройках MCP».

| Ключ | Что открывает |
|---|---|
| (чтение) | всегда: статус, конфиг (редактированный), логи, списки, каталоги, результаты |
| `control` | start/stop/restart движков, применение существующих стратегий, SIGHUP |
| `strategies_write` | CRUD user-стратегий, hostlist'ов, ipset'ов, blob'ов, lua |
| `config_write` | запись настроек в whitelisted-поддеревья |
| `probes` | **активные пробы**: трафик с роутера, blockcheck, сканер |
| `experiments` | движок экспериментов (требует `control` и `probes`) |
| `tunnels_write` | конфиги и запуск sing-box/mihomo/AWG/usque/tgproxy/opera |
| `dangerous` | бинари, автозапуск, миграции, `unified`-правила, перезагрузка |
| `shell_readonly` | safe-список команд, чтение файлов, листинг каталогов |
| `shell_full` | произвольная команда, запись файлов, пакеты, службы — **root** |
| `self_edit` | чтение и правка модулей GUI + перезапуск под сторожем |
| `self_edit_core` | вдобавок «защищённое ядро» (`auth.py`, `permissions.py`, `code_guard.py`, `config_manager.py`) |

Два принципа, взятых у b4 и верных:

1. **Выпустить трафик — не то же самое, что записать настройку.** Поэтому
   `probes` — отдельное разрешение, а не часть чтения.
2. **Граница записи проходит по обратимости, а не по чувствительности.**
   Неверное значение внутри стратегии ломает часть сайтов — это видно и
   откатывается одним вызовом; неверный порт GUI, бэкенд firewall или
   desync-метка оставляют роутер недоступным без пути назад. Первое отдаём
   на запись, второе — нет, как бы полезно оно ни выглядело.

## 5. Инварианты безопасности (действуют во всех сессиях)

1. **Read-only по умолчанию.** MCP выключен, токен пуст, все разрешения
   `false`. Новая настройка по умолчанию **не** доступна на запись.
2. **Секреты не покидают роутер.** Единая `core/mcp/redact.py`, применяется
   в **одной** точке — сериализации результата инструмента. Тест-сторож
   перебирает все инструменты.
3. **Аудит каждого `tools/call`** (JSONL + лог-буфер, `source="mcp"`).
   Отклонённый вызов — `warning`; отказы на точке доступа сворачиваются
   (строка в 30 с со счётчиком). **Токен не пишется в лог никогда.**
   Мутирующий вызов пишет снимок «до» для `mcp_undo_last`.
4. **Любое изменение состояния обратимо**: снимок + `undo` либо TTL +
   авто-откат (дедмен-свитч). Это касается экспериментов, firewall из MCP,
   сетевых shell-команд и правок кода.
5. **Не рвать управление.** Порт GUI и SSH исключаются из любых
   firewall-операций из MCP. После любой последовательности вызовов — в том
   числе намеренно вредных — GUI и SSH остаются доступны сами.
6. **Промпт-инъекция.** Логи, домены, имена конфигов, вывод blockcheck и
   содержимое файлов — данные из внешнего мира: помечаются `untrusted data`
   в описаниях инструментов и не форматируются как инструкции.
7. **Нет инструмента `teardown`.** Снос runtime-артефактов — только через
   shell при полном доступе, осознанно. Зафиксировано тестом.

## 6. Бюджет чтения

**Читать целиком** можно файл до ~300 строк. Больше — `grep -n` по именам и
`sed -n 'A,Bp'` по найденным диапазонам.

**Никогда не открывать целиком:** `core/strategy_scanner.py`,
`core/firewall.py`, `core/blockcheck.py`, `core/diagnostics.py`,
`web/js/pages/strategies.js`, `app.py`, `api/*.py` пачкой, `tests/*` пачкой,
`docs/mcp-server-plan.md`.

**Скил nfqws2 — по разделам.** Целиком он нужен только S11. Остальным хватает
§2 (инварианты), §12 (сборка argv), §13 (сканер).

**Разведку отдавать субагенту** `Explore` («найди, где регистрируются роуты и
как устроен ответ ошибки») — в основной контекст вернётся абзац, а не
пол-репозитория.

**Тесты гонять точечно:** `python3 -m pytest tests/test_mcp_*.py -q`. Полный
прогон — один раз в конце сессии.

## 7. Регламент сессии

**Старт (в этом порядке, ничего лишнего):**

1. этот файл (`00-contract.md`);
2. своё задание `docs/mcp/NN-*.md`;
3. `docs/mcp/HANDOFF.md` — что оставила предыдущая сессия;
4. `.claude/skills/mcp/SKILL.md` — текущий слепок реализации (с S2);
5. точечная разведка по именам из задания.

**Работа:** сначала один эталонный кусок целиком (первый инструмент, первый
метод) — остальное по его образцу. Тесты пишутся в той же сессии, что и код;
**сессия без тестов не закрывается**.

**Финиш (обязательный ритуал):**

1. `python3 -m pytest tests/test_mcp_*.py -q` → `python3 -m pytest tests/ -q`
   → `make lint`;
2. обновить `.claude/skills/mcp/SKILL.md` (новые инструменты, контракты, грабли);
3. перезаписать `docs/mcp/HANDOFF.md` (шаблон — в самом файле);
4. `CHANGELOG.md`, коммит, PR.

**Когда останавливаться, не доделав:** контекст перевалил за 60%, начались
авто-компакты или дифф вырос за ~700 строк. Тогда: дописать HANDOFF,
закоммитить то, что работает и покрыто тестами, остаток переписать в задание
следующей сессии. Половина PR с зелёными тестами лучше, чем целый PR,
собранный после трёх компактов.
