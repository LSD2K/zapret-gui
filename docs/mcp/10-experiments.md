### Контракт (`core/strategy_experiment.py`)

```python
runner.start(
    variants=[                      # 1..mcp.experiment.max_variants
        {"label": "A", "args": ["--filter-tcp=443", "--lua-desync=fake:..."]},
        {"label": "B", "strategy_id": "tcp_oob"},
        {"label": "C", "profiles": [...]},        # декларативно (S11)
    ],
    targets=["youtube.com", "rutracker.org"],     # ≤ max_targets; дефолт — core/targets.py
    probes=["tls", "http", "body", "quic"],
    repeats=2,
    baseline=True,        # прогнать без обхода
    ttl_sec=180,          # дедмен-свитч
    keep_best=False,
) -> {"ok": True, "run_id": "exp-20260916-153012"}
```

`get_status()` → `{state: idle|running|finished|failed|reverted, run_id,
variant, variant_index, total, phase, progress, eta_sec, ttl_left_sec}`.

`get_result(run_id=None)` → компактный отчёт: `baseline` по целям, массив
`variants` (label, args, `validation`, `started_nfqws`, `per_target` с кодом/
латентностью/скоростью, `success_rate`, `score`, `delta_vs_baseline`,
`nfqws_log` ≤ 20 строк, `hints`), `best`, `ranking`, `warnings`.
Полный пример — §8.1 плана (`grep -n "run_id.*exp-2026" -A 40 docs/mcp-server-plan.md`).

### Как исполняется один вариант

1. **Мьютекс** `core/nfqws_session.py` (общий со сканером). Занято → `isError`
   «идёт скан, остановите его или дождитесь» + имя владельца.
2. **Снимок состояния** через тот же модуль.
3. **Baseline** (если запрошен): остановить обход, прогнать пробы.
   Логика «цель открыта и без обхода ⇒ любые выводы недостоверны» уже есть в
   сканере — переиспользовать.
4. Для каждого варианта: валидация (dry-run) → применить firewall + запустить
   nfqws2 → `stabilize_sec` → пробы (`repeats` раз, брать **медиану**) →
   снять хвост лога `source="nfqws"` за окно варианта → остановить.
5. **Автовосстановление в `finally` на каждом шаге** + поток-дедмен: не
   пришёл `commit` за `ttl_sec` → вернуть снимок, пометить прогон `reverted`.
6. `commit(label)` — оставить вариант применённым, при желании сохранить
   user-стратегией (`strategy_save` из S7) и сделать активным.

### Метрики и «почему не сработало»

- Коды проб — только `PROBE_CODES`, никаких свободных строк: модель должна
  получать стабильные символы.
- `score` — **формула сканера**, чтобы ранжирование совпадало с тем, что
  показывает UI.
- `hints` — правила-детекторы поверх лога и кодов, каждая строка со ссылкой
  на раздел скила:

| Что в логе/кодах | Подсказка |
|---|---|
| `rawsend: Operation not permitted` | проверь POSTNAT-правила и `desync_mark_postnat` |
| `lua: attempt to call a nil value` | неизвестная lua-функция → `lua_functions_list` |
| 0% на всех целях при валидном dry-run | проверь NFQUEUE-правила и `queue_num` |
| падает при старте | проверь `--user` и права |

Правила-детекторы вынести **данными** (список пар «паттерн → подсказка»), а
не цепочкой `if` — S11 будет их дополнять.

## Приёмка

- На dev-машине **без nfqws2** движок корректно говорит «бинарь недоступен»
  и ничего не ломает.
- На устройстве — полный цикл A/B с авто-откатом по TTL.
- Одновременный запуск со сканером отклоняется.
- Отчёт по трём вариантам и двум целям влезает в лимит ответа.
- **Прерывание питания посреди эксперимента не оставляет применённой
  временную стратегию** (проверить: снимок на диске, восстановление при
  старте GUI). Это пункт 3 приёмки фичи целиком (§17 плана).

## Грабли

- **Медиана, а не среднее.** Один выброс по латентности на роутере — норма.
- **Хвост лога надо резать по окну варианта**, иначе в отчёт попадёт лог
  предыдущего и модель будет чинить не то.
- **`keep_best` без `commit` — ловушка.** Если вариант оставлен применённым,
  дедмен всё равно должен сработать: «оставить лучший» ≠ «подтвердить».
  Явно решить и записать в скил.
- **Не переписывай сканер.** Ты переиспользуешь его baseline и score; всё,
  что нужно вынести, уже вынесено в S9.
- Длинные прогоны — асинхронные (контракт S8), `start` возвращает `run_id`
  мгновенно.
