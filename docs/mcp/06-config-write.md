# S6 — Запись настроек, аудит, undo

> Вход: [`00-contract.md`](00-contract.md) + этот файл + `HANDOFF.md` + скил `mcp`.
> Первая сессия, где модель **что-то меняет**. Всё, что здесь заложено
> (журнал, снимки, `undo`), потом переиспользуют S7, S12 и S13 — поэтому
> механика важнее числа инструментов.

## Что прочитать (≈25K)

- `core/mcp/permissions.py` из S2 — целиком (whitelist уже там).
- `core/config_manager.py` — **точечно**: запись, слияние, атомарность,
  права файла (`grep -n "def set\|def save\|def update\|atomic\|0o600"`).
- `core/safe_io.py` — целиком (небольшой): `atomic_write_*`.
- `core/log_buffer.py` — как писать строку с `source="mcp"`.
- `core/platform_dirs.py` — `grep -n "def "`: куда класть `mcp-audit.jsonl`
  (рядом с `settings.json`, а не в `/tmp`: `/tmp` на роутере чистится).

## Что написать

```
core/mcp/audit.py            — журнал вызовов (JSONL + ротация) + снимки для undo
core/mcp/tools/config.py     — дополнить: config_set, config_writable_paths
core/mcp/tools/audit.py      — audit_list, mcp_undo_last
```

### 1. `config_set` (`config_write`)

- Только whitelisted пути (`permissions.is_writable`); deny-поля имеют
  приоритет.
- Валидация типа **по значению из `DEFAULT_CONFIG`**: строка не должна
  молча стать числом.
- Ответ — **diff «было/стало»**, а не `{ok: true}`: модель должна видеть,
  что именно изменилось.
- Отказ — с подсказкой: почему путь не writable и что можно вместо него
  (сослаться на `config_writable_paths` и `config_describe` из S3).
- **Списочные настройки заменяются целиком, а не дополняются.** `config_set`
  для списка обязан вернуть прежнее значение в ответе, а в описании
  инструмента должно быть написано: *прочитай текущее значение и верни его
  полностью*. Иначе модель «добавит домен», стерев остальные. Это
  единственное место, где формулировка описания важнее кода.

### 2. `config_writable_paths` (чтение)

Какие настройки модель может менять: путь, тип, текущее значение, допустимые
значения. Нужен, чтобы не угадывать путь и не получать отказ за отказом.

### 3. Аудит (`core/mcp/audit.py`)

Каждый `tools/call`: время, инструмент, адрес вызывающего, аргументы
(**после** редактирования), результат (ok/ошибка), длительность → JSONL
`mcp-audit.jsonl` с ротацией по `mcp.audit.keep` + строка в лог-буфер
(`source="mcp"`).

- Отклонённый вызов пишется на уровне **warning**: попытка сделать то, на
  что прав не давали, должна быть заметна на фоне обычной работы.
- Отказы на самой точке доступа (сервер выключен, токен неверен, чужой
  Origin) — **сворачиваются**: одна строка раз в 30 с со счётчиком (это уже
  сделано в S1 — здесь только свести в один журнал).
- **Токен не пишется никогда.**
- Мутирующий вызов дополнительно пишет **снимок «до»**.

### 4. `mcp_undo_last` (`config_write`)

Откат последнего мутирующего вызова по снимку из аудита. Ключевое отличие
от b4 (у них история в памяти, перезапуск чистит): **у нас журнал и снимки
на диске** — роутер перезагружается чаще, чем хочется, а «верни как было»
нужно именно после неудачного эксперимента. `mcp_undo_last` обязан работать
и после рестарта GUI.

Формат снимка держать **обобщённым**, не «под настройки»: `{kind, target,
before, after}`. В S7 туда лягут стратегии и списки, в S12 — файлы
(`file_write`), в S13 `mcp_undo_last` для правок кода становится
`code_rollback`. Заложи это сразу — переделывать формат журнала задним
числом дорого.

### 5. `audit_list` (чтение)

Последние вызовы MCP — для самоконтроля модели и человека. С пагинацией,
редактированные аргументы, без токенов.

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_mcp_writable_paths.py` | **сторож**: каждый ключ `DEFAULT_CONFIG` отнесён либо к writable, либо к non-writable; новый ключ ломает тест, пока его явно не отнесли (если тест уже заведён в S2 — дополнить) |
| `tests/test_mcp_config_write.py` | запись вне whitelist'а отклоняется с подсказкой; deny-поле внутри writable-поддерева отклоняется; неверный тип отклоняется; ответ содержит diff; список заменяется целиком и прежнее значение возвращается |
| `tests/test_mcp_audit.py` | мутирующий вызов пишет снимок; `mcp_undo_last` возвращает прежнее значение; журнал переживает «перезапуск» (перечитать файл новым объектом); ротация по `keep`; отклонённый вызов пишется как warning; токен не попадает в журнал |

## Приёмка

- Запись вне whitelist'а невозможна ни одним путём (включая `a.b.c` с
  несуществующим промежуточным узлом и путь с `..`-подобными трюками).
- Каждый мутирующий вызов виден в журнале и откатывается.
- `mcp.*` и `gui.*` не записываются даже при `config_write=true`.

## Грабли

- **Не писать `settings.json` мимо `config_manager`.** Атомарность, слияние
  с дефолтами и права `0600` уже решены там.
- **Ротация журнала не должна терять снимок, нужный `undo`.** Последний
  мутирующий вызов обязан переживать ротацию — храни снимки отдельным
  файлом или закрепляй последний.
- **JSONL пишется построчно и флашится.** Роутер выключают розеткой; пол
  строки в конце файла не должны ронять чтение журнала (битая строка —
  пропустить, а не падать).
- Журнал в `/tmp` — ошибка: там `tmpfs`, и он не переживёт перезагрузку.

## Оставить следующим

`HANDOFF.md` + скил: формат записи журнала и снимка (обобщённый `{kind,
target, before, after}`), как вызывается `undo` для разных `kind`, где лежит
файл, как тесты подменяют его путь.
