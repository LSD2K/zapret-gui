# S2 — Реестр, разрешения, секреты

> Вход: [`00-contract.md`](00-contract.md) + этот файл + `HANDOFF.md`.
> **Самая влиятельная сессия проекта после S1:** написанный здесь эталон
> инструмента копируют все следующие сессии. Форма важнее объёма — четыре
> инструмента, сделанных правильно, полезнее двадцати, сделанных наспех.

## Что прочитать (≈22K)

- `core/mcp/server.py`, `core/mcp/schema.py`, `api/mcp.py` — написанное в S1,
  целиком (они небольшие).
- `core/config_manager.py` — **точечно**: как читаются значения по пути

- Образец теста-сторожа: `tests/test_agent_skill_index.py` — по нему делается

## Что написать

```
core/mcp/registry.py     — @tool(...) + сбор списка по разрешениям
core/mcp/permissions.py  — переключатели, writable-поддеревья, deny-поля
core/mcp/redact.py       — вырезание секретов из любого ответа
core/mcp/tools/__init__.py  — автозагрузка модулей инструментов
core/mcp/tools/status.py    — system_status, nfqws_status (переезд из S1)

core/mcp/tools/logs.py      — logs_tail
.claude/skills/mcp/SKILL.md — первая версия
```

### 1. Реестр (`core/mcp/registry.py`)

Декоратор `@tool(name, scope, mutating, title, description, schema)` —
сигнатура и пример в [контракте §3](00-contract.md). Реестр:

- собирает инструменты в словарь по имени при импорте модулей
  `core/mcp/tools/*` (автозагрузка через `pkgutil.iter_modules`, без
  явного перечисления — новый модуль подхватывается сам);
- `list_tools(permissions) -> list[dict]` — **только разрешённые**,
  отсортированные по имени, с `cursor`-пагинацией;
- `call(name, args, permissions)` — проверка разрешения → валидация
  аргументов по схеме → вызов → `redact()` → обрезка до
  `mcp.limits.response_kb` → форма ответа из контракта;
- вызов неразрешённого инструмента: `isError` + текст «инструмент
  недоступен: включите разрешение X в настройках MCP» (не `-32601` — модель
  должна понять, что делать);
- имя не в snake_case, пустое описание, описание > 300 символов, отсутствие
  `scope`/`mutating` — **исключение при импорте**, а не тихая регистрация.

### 2. Разрешения (`core/mcp/permissions.py`)

- Чтение разрешений из `settings.json → mcp.permissions`, значения по
  умолчанию `False`; чтение — всегда доступно.
- `experiments` без `control` и `probes` **не включается** (возвращать
  причину, а не молча игнорировать).
- **Whitelist записи в `settings.json`** — явный список путей-поддеревьев:
  `nfqws.*` (кроме `desync_mark*`, `queue_num`, `user`), `filter.*`,
  `strategy.*`, `lists.*`, `blockcheck.*`, `healthcheck.*`, `scan.*`,
  `block_detector.*`, `dns_routing.*`, `logging.*` (чтобы модель могла
  поднять уровень лога, воспроизвести проблему и прочитать результат).
- **Deny-поля имеют приоритет** и включают, помимо очевидных секретов:
  - `gui.*` — перенос или блокировка интерфейса убирает способ отменить
    изменение;
  - `mcp.*` — модель не расширяет собственные права;
  - `firewall.type`, `nfqws.desync_mark*`, `nfqws.queue_num` — на них
    держится перехват и собственный трафик;
  - `zapret.*_path`, `install.*` и прочие **расположения** файлов и
    каталогов: неверный путь не «ломает громко», а тихо выключает часть
    логики. Отклоняем **расположение**, но не содержимое — читать и править
    сами списки/lua модель может через `strategies_write`.
- Функции: `is_writable(path) -> bool`, `writable_paths() -> list[dict]`
  (путь, тип, текущее значение, допустимые значения) — вторая нужна
  инструменту `config_writable_paths` (S6).

Саму запись (`config_set`) делает **S6**. Здесь — только модель и проверки.

### 3. Редактирование секретов (`core/mcp/redact.py`)

Применяется в **одной** точке — сериализации результата инструмента,
рекурсивно по dict/list/str:

- ключи, совпадающие с `(?i)pass|secret|token|key|licen|uuid|auth|credential`
  → `"***"`;
- `private_key`, `preshared_key` → `"***"`;
- URL подписок → `https://host/…` (хост оставляем, путь и query режем);
- **hostlist'ы и домены не трогаем** — это рабочие данные модели;
- функция должна уметь работать и по «сырому тексту» (пригодится S12 для
  вывода shell-команд).

### 4. Четыре инструмента как эталон формы

`system_status`, `nfqws_status` (переезд из S1 под `@tool`), `config_get`
(`path` — точечный путь, `depth` — ограничение глубины, ответ
редактированный), `logs_tail` (`source`, `level`, `search`, `limit` ≤ 200,
`since`).

Каждый — с полным `description` (EN + RU), схемой, docstring'ом по-русски и
компактным ответом. Именно эти четыре следующие сессии будут открывать как
образец, поэтому: одинаковые имена полей, одинаковая обработка «нет данных»,
одинаковые лимиты и пагинация.

### 5. Скил `.claude/skills/mcp/SKILL.md` (первая версия)

Не «когда устаканится», а **сейчас**: он заменяет следующим сессиям чтение
уже написанного кода. Первая версия (≈150 строк, вырастет до 300–400):
frontmatter с описанием, ревизия спеки, наш транспорт и авторизация, форма
инструмента, таблица разрешений, таблица инструментов (пока 4 строки),
правила редактирования секретов, грабли. После добавления —
`python3 tools/gen_agent_index.py` (скил попадёт в индекс `AGENTS.md`).

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_mcp_permissions.py` | `tools/list` меняется от переключателей; запрещённый инструмент не вызывается по имени; `experiments` без `control`/`probes` не включается |
| `tests/test_mcp_redaction.py` | сторож: прогнать **все** read-only инструменты на фикстуре `settings.json` с известными секретами и убедиться, что ни один не утёк ни в `content`, ни в `structuredContent`. Тест обязан перебирать реестр, а не список имён руками — иначе новый инструмент в него не попадёт |
| `tests/test_mcp_tool_counts.py` | число публикуемых инструментов для каждой комбинации разрешений зафиксировано (как таблица 13/15/17/19 у b4): случайное «протекание» инструмента в read-only набор ломает тест |
| `tests/test_mcp_schema.py` (дополнить) | у каждого инструмента: валидная схема, непустое описание ≤ 300 символов, snake_case-имя, объявлены `scope`/`mutating` |

`tests/test_mcp_writable_paths.py` — сторож, который проходит по всем ключам
`DEFAULT_CONFIG` и требует, чтобы каждый был явно отнесён к writable или
non-writable. **Можно завести здесь** (модель путей готова) — тогда S6
получит его бесплатно. Если не успеваешь — отдать в S6 и записать в HANDOFF.

## Приёмка

- Добавление нового модуля в `core/mcp/tools/` подхватывается без правки
  реестра.
- Выключение разрешения немедленно убирает инструменты из `tools/list` —
  без перезапуска GUI.
- Тест редактирования секретов **сам находит** новые инструменты.
- `python3 tools/gen_agent_index.py --check` зелёный.

## Грабли

- **Автозагрузка и циклические импорты.** `core/mcp/tools/*` импортируют
  менеджеры, менеджеры не должны импортировать MCP. Импорт модулей
  инструментов — **лениво**, при первом обращении к реестру, а не на
  импорте `core.mcp`.
- **Редактирование — не поиск по значению.** Не пытайся искать «похожее на
  токен» в строках: маскируй по ключам и по известным полям, иначе
  замаскируешь домены и аргументы стратегий.
- **Счётчик инструментов — это контракт с UI** (S15 показывает число). Не
  прятать инструмент целиком, если часть его действий читает, а часть
  пробует: публикуем всегда, проверяем действия по отдельности (так у b4 с
  `b4_watchdog`, и это лучше).
