# S3 — Ресурсы и справочники

> Вход: [`00-contract.md`](00-contract.md) + этот файл + `HANDOFF.md` + скил `mcp`.
> Смысл сессии одной фразой: **без справочника модель сочиняет флаги.**
> Это наблюдение b4, и оно решает судьбу всей затеи — S10/S11 без S3
> бессмысленны.

## Что прочитать (≈25K)

- `core/mcp/registry.py` + один эталонный инструмент из S2 — целиком.
- `core/lua_manager.py` — **точечно** (`grep -n "def \|FUNCTIONS\|EXTENSIONS"`):
  нужна карта lua-функций с параметрами.
- `core/catalog_loader.py` — `grep -n "def "`: как читаются `catalogs/*`.
- `core/nfqws_manager.py` — **только** `grep -n "def dry_run\|def compose_command\|def get_status\|binary\|-?"`:
  нужен способ получить живой вывод `nfqws2 -?` с устройства.
- `.claude/skills/nfqws2-strategies/SKILL.md` — **не целиком**: только
  оглавление (`grep -n '^#'`), чтобы понять, что отдавать ресурсом.
- `tests/test_lua_symbols_resolve.py` — как проект уже проверяет, что
  lua-имена резолвятся (родственный инвариант).

## Что написать

```
core/mcp/resources.py       — ресурсы zapret://…
core/mcp/prompts.py         — шаблоны сценариев
core/mcp/tools/docs.py      — docs_get, config_describe
```

### 1. Ресурсы (`core/mcp/resources.py`)

URI-схема `zapret://…`. Что отдаём:

| URI | Содержимое |
|---|---|
| `zapret://docs/overview` | что это за сервер, что модель может и чего не может, с какого инструмента начинать |
| `zapret://skills/nfqws2` | скил nfqws2 (по разделам: `?section=12`, целиком — тоже можно, но с предупреждением о размере) |
| `zapret://nfqws2/cli` | **живой вывод `nfqws2 -?` с этого устройства** (кэш на время жизни процесса; бинаря нет → честное «недоступно» с причиной) |
| `zapret://nfqws2/lua` | карта `--lua-desync` функций: имя, параметры, требования, какой blob нужен |
| `zapret://catalogs/<имя>` | каталоги стратегий |
| `zapret://state/current` | текущее состояние: что запущено, активная стратегия, применён ли firewall |
| `zapret://config/describe` | описания настроек (см. ниже) |

`resources/list`, `resources/read`, `resources/templates/list` — заполнить
по-настоящему (в S1 они отвечали пустым списком).

### 2. Зеркало «ресурс = инструмент» (ключевое требование)

**Многие клиенты — LM Studio и OpenAI-совместимые мосты — показывают ресурсы
пользователю, а не модели.** Описание, доступное только как ресурс, — это
описание, которое модель никогда не прочитает. Поэтому:

- `docs_get` — тот же текст, что и ресурсы `zapret://…`, но инструментом.
  Аргументы: `uri` или `topic`, `section`, `offset`/`limit` (скил большой —
  обязательна пагинация и `truncated: true`).
- `config_describe` — описание настройки: тип, дефолт, что делает, в чём
  измеряется, **что означает `0`/пустое значение**, writable ли для MCP.
  Принимает точный ключ, путь или поисковый запрос; без аргументов —
  перечисляет все документированные ключи.
  **Если описания нет** — так и отвечает, плюс отдаёт список документированных
  рядом: пусть модель скажет «не уверена», а не угадывает смысл по имени поля.

Тест-сторож `test_mcp_resources_mirror.py` фиксирует зеркало: каждый ресурс
доступен и через инструмент **с тем же содержимым**.

### 3. Источник описаний настроек

Отдельный словарь (`core/mcp/config_docs.py` или данные внутри
`resources.py` — на твоё усмотрение, но **данные, а не код**): ключ → {тип,
дефолт, единица, описание по-русски, что значит 0/пусто}. Заполнить для
writable-путей из S2 и для того, что модель точно спросит (`nfqws.*`,
`filter.*`, `strategy.*`, `lists.*`, `logging.*`). Остальное честно
отвечает «описания нет».

### 4. Промты (`core/mcp/prompts.py`)

`prompts/list` и `prompts/get` с готовыми сценариями:

1. «подобрать стратегию для домена» — порядок вызовов из §8.4 плана:
   `lua_functions_list`/`catalog_search` → `strategy_compose` →
   `strategy_validate` → `strategy_experiment_start` → `..._result` →
   правка → `..._commit` + `strategy_save`;
2. «разобрать, почему домен не открывается» — `probe_targets` → `dpi_report`
   → `logs_tail`;
3. «проверить здоровье роутера» — `system_status` → `diagnostics_run` →
   `tunnels_status`.

Промт ссылается на инструменты **по именам**, даже если их ещё нет (они
появятся в S4–S10). В тексте промта — пометка про `untrusted data`: логи,
домены и вывод blockcheck приходят из внешнего мира.

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_mcp_resources_mirror.py` | каждый ресурс `zapret://…` доступен и через `docs_get`/`config_describe` с тем же содержимым; запрос недокументированной настройки возвращает пометку «нет описания» + список документированных |
| `tests/test_mcp_resources.py` | `resources/list`/`read`/`templates/list`; неизвестный URI → понятная ошибка; `zapret://nfqws2/cli` без бинаря отвечает «недоступно», а не падает; пагинация большого скила |
| `tests/test_mcp_prompts.py` | `prompts/list`/`get`; каждый упомянутый в промте инструмент либо существует, либо явно помечен как «появится позже» (иначе промт врёт модели) |

## Приёмка

- Модель, подключённая read-only, может объяснить состояние роутера и
  предложить стратегию, **не имея права ничего менять**.
- `zapret://nfqws2/cli` отдаёт вывод именно **этого** бинаря, а не
  захардкоженный текст: на устройстве с другой версией zapret2 содержимое
  другое.
- Ответ `docs_get` укладывается в `mcp.limits.response_kb` при любом
  запросе (скил nfqws2 — 93 КБ, целиком он в ответ не влезает by design).

## Грабли

- **Не копировать скил в код.** Читать файл с диска
  (`.claude/skills/nfqws2-strategies/SKILL.md`), иначе он разойдётся с
  оригиналом в первый же апстрим-дрифт. Если файла на устройстве нет
  (пакет ставится без `.claude/`) — честно сказать, что справочник
  недоступен, и назвать URL.
- **Карта lua-функций — из `lua_manager`, а не руками.** Иначе получим ровно
  тот «тихий 0%», против которого этот инструмент и задуман.
- **Кэш `nfqws2 -?`** — на время жизни процесса, но с инвалидизацией при
  смене пути к бинарю: после обновления zapret2 справка меняется.
