# S13 — Самоправка кода GUI на устройстве

> Вход: [`00-contract.md`](00-contract.md) + этот файл + `HANDOFF.md` + скил `mcp`.
> **Самый опасный инструмент набора:** MCP-сервер живёт *внутри* того
> процесса, который модель переписывает. Всё здесь построено вокруг одной
> мысли — сломанный GUI не поднимет ни MCP, ни свой собственный откат,
> поэтому откатывать должен **посторонний процесс**.

## Что прочитать (≈22K)

- `core/system_control.py` — целиком: как уже запускается отвязанный процесс
  и рестарт GUI. `core/code_guard.py` делается по этому образцу.
- `core/safe_io.py` — `atomic_write_*`.
- `core/mcp/audit.py` (S6) — снимки; `core/shell_exec.py` (S12) — запуск
  подпроцессов с таймаутом (переиспользовать, не писать второй).
- `core/platform_dirs.py` — куда класть `code-snapshots/`.
- `grep -n "def status" api/status.py` — что именно считается «GUI жив».

## Что написать

```
core/code_editor.py          — правка файлов GUI: границы, staging, снимки, проверки
core/code_guard.py           — сторож перезапуска: health-check и авто-восстановление
core/mcp/tools/code.py       — code_* (13 инструментов)
```

| Инструмент | Что делает |
|---|---|
| `code_tree` | дерево файлов проекта: путь, размер, mtime, признак «защищённый»; фильтр по маске, пагинация |
| `code_read` | прочитать файл с номерами строк: `path`, `offset`, `limit` |
| `code_search` | поиск по коду (подстрока/регэксп) с контекстом ±2 строки — чтобы модель не читала файлы целиком и не жгла контекст |
| `code_patch` | точечная правка: `path` + список `{old, new}` (точное совпадение) **или** unified diff. Неоднозначное совпадение — отказ с указанием, сколько раз найдено |
| `code_write` | полная перезапись/создание файла (для новых модулей) |
| `code_check` | проверки **без применения**: `.py` → `ast.parse` + `python3 -c "import <module>"` в подпроцессе; `.json` → `json.loads`; `.js` → `node --check`, если node есть; плюс эквивалент `make lint` |
| `code_test` | `python3 -m pytest tests/ -q -k <pattern>` с таймаутом; нет pytest — честно `available: false` |
| `code_apply` | применить накопленные правки: снимок → проверки → перезапуск под сторожем → ждать живой `/api/status` |
| `code_commit` | подтвердить применённую правку (иначе откат по `commit_ttl_sec`) |
| `code_rollback` | откат к снимку: последнему или по `snapshot_id` |
| `code_history` | снимки: id, время, файлы, размер diff, статус (committed/reverted/pending) |
| `code_diff` | unified diff: рабочее дерево против снимка или против эталона релиза |
| `code_export_patch` | все локальные правки одним unified diff — чтобы перенести их в репозиторий, а не потерять при обновлении GUI |

Все — под `self_edit`; файлы из `self_edit.protected` требуют
`self_edit_core`.

## Механика (это и есть суть сессии)

1. **Границы.** Разрешён только каталог установки GUI (автодетект по
   `__file__`, переопределяется `self_edit.root`). Путь нормализуется; `..`
   и симлинки наружу отклоняются. `self_edit.protected` —
   `core/mcp/auth.py`, `core/mcp/permissions.py`, `core/code_guard.py`,
   `core/config_manager.py`: то, чем держится сама защита.
2. **Снимок.** Перед первой правкой в сессии — копия затрагиваемых файлов в
   `<config_dir>/code-snapshots/<timestamp>/` + манифест (пути, sha256,
   версия GUI). Хранится `snapshots_keep` штук. Если каталог установки —
   git-репозиторий, дополнительно фиксируется `git rev-parse HEAD` и
   `git diff`, **но зависимости от git нет** (на роутере его обычно нет).
3. **Проверки до применения.** Синтаксис → импорт модуля в отдельном
   процессе (`python3 -c "import core.foo"` с `cwd` проекта) → опционально
   тесты. Любая упавшая проверка = отказ, **файл на диске не тронут**:
   правки копятся в staging-копии и кладутся на место атомарно.
4. **Перезапуск под сторожем.** `code_apply` запускает
   `python3 -m core.code_guard --snapshot <id> --timeout <restart_timeout_sec>`
   **отдельным отвязанным процессом** — и только потом просит GUI
   перезапуститься. Сторож ждёт, пока `/api/status` снова начнёт отвечать:
   - ответил → пишет в снимок `applied`, ждёт `code_commit` до
     `commit_ttl_sec`; не дождался → восстанавливает файлы и рестартует снова;
   - не ответил за `restart_timeout_sec` → немедленно восстанавливает снимок,
     рестартует GUI, пишет причину в **персистентный** лог.
5. **Разрыв сессии.** Рестарт рвёт HTTP-соединение — MCP-клиент увидит
   ошибку. В описании `code_apply` явно сказать модели: *«после вызова
   подожди 5–10 секунд, повтори `system_status`, затем вызови `code_commit`»*.
   Тот же текст — в скиле `mcp` и в README.
6. **Аудит.** Каждая правка: файл, размер diff, сам diff (обрезанный),
   результат проверок, статус применения. `mcp_undo_last` для правок кода
   равен `code_rollback`.
7. **Расхождение с репозиторием.** Правки на устройстве живут до следующего
   обновления GUI. `code_export_patch` + предупреждение при `gui_update`:
   «на устройстве есть локальные правки (N файлов), обновление их затрёт;
   выгрузи патч». Удачные находки должны доезжать до репозитория.

Удачный цикл целиком — Приложение E плана
(`grep -n "Приложение E" -A 25 docs/mcp-server-plan.md`).

## Тесты

| Файл | Что фиксирует |
|---|---|
| `tests/test_mcp_code_editor.py` | границы каталога (`..`, симлинк наружу, абсолютный путь вне root — отказ); `code_patch` с неоднозначным совпадением отклоняется; правка защищённого файла без `self_edit_core` отклоняется; битый синтаксис не доезжает до диска; снимок создаётся и содержит прежнее содержимое |
| `tests/test_mcp_code_guard.py` | сторож восстанавливает снимок, если health-check не прошёл; откатывает по `commit_ttl_sec` без `code_commit`; `code_commit` отменяет откат; ротация снимков (`snapshots_keep`) |

Тесты сторожа гонять с маленькими таймаутами и подменённым health-check'ом,
не поднимая настоящий GUI.

## Приёмка

- Правка модуля с ошибкой синтаксиса **до диска не доезжает**.
- Удачная правка применяется и переживает рестарт.
- **Намеренно сломанный** модуль (например, `raise` на импорте) приводит к
  автоматическому восстановлению GUI сторожем — **проверить руками на
  устройстве, это главный тест фичи**.
- Без `code_commit` правка откатывается по TTL.
- Локальные правки выгружаются одним патчем и применяются в репозитории.

## Грабли

- **Сторож, запущенный из умирающего процесса, умрёт вместе с ним.** Отвязка
  (`setsid`/двойной fork, как в `core/system_control.py`) — не деталь, а
  единственное, что делает всю схему работающей.
- **`import core.foo` в подпроцессе может «пройти» из-за `.pyc`.** Запускать
  с чистым окружением и правильным `cwd`.
- **Проверка «GUI жив» должна быть содержательной.** TCP-коннект недостаточен:
  спрашивать `/api/status` и проверять тело ответа.
- **Не давай модели править `core/code_guard.py` без `self_edit_core`** — это
  ровно тот файл, который её и откатывает.
- **Снимок должен пережить перезагрузку роутера** посреди применения: манифест
  пишется до правки файлов, восстановление возможно при следующем старте.
